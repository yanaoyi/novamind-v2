## 一、固定测试剧本（任务书 §9.6 第一条）

脚本：`scripts/acceptance-phase9.sh`。剧本与断言：

| 步骤 | 断言 | 结果 |
|---|---|---|
| 造原著 3 章并导入（第 1 章埋伏笔：左肩中箭 + 青铜钥匙） | 切分 3 章；索引由导入自动触发并完成 | ✅ |
| 新开二创 → 继承世界 → 加世界规则「夜禁」 | 接口全部 2xx | ✅ |
| 作者写 3 章（第 3 章埋预设矛盾：子时出城 + 左肩中箭却单臂举三百斤） | 3 章摘要自动产生；事实 ≥3 条且含伤情；章节/记忆/规则都进检索索引 | ✅ |
| AI 写第 4 章（目标点名"青铜钥匙"） | 第 4 章快照的 `retrieved_creative` 含"青铜钥匙"；`retrieved_sources` 能指到**第 1 章**的 chunk | ✅ |
| 对第 3 章做一致性检查 | 系统指出问题 | ✅ |

**第 5 步系统实际给出的问题（原文摘录）**：

```
· [high/plot] 与既有内容中的伤情设定冲突：既有章节与记忆事实一致确立沈砚左肩中箭
  仅三日、伤口未愈（第1章"左肩的箭伤被雨水泡得发白……
```

这条正是"越写越懂"的证据：检查器不是靠"感觉"，而是靠**第 1 章写下的伤情事实**判断第 3 章不成立。
第 4 章快照里记的是 `deepseek-chat / chapter_generate.v3`。

结果：**11 项断言全部通过**。

## 二、逐链路冒烟（任务书 §9.6 第三条）

## 三、检索性能基线（任务书 §9.6 第四条）

`scripts/smoke-phase9-retrieval.sh`：100 章原著（约 17 万字）→ 300 块 → 30 次检索采样。

| 指标 | 值 | 要求 |
|---|---|---|
| 中位数 | 0.019s | — |
| **P95** | **0.024s** | **< 2s ✅** |
| 最大 | 0.025s | — |
| 召回（5 个 query，top8 命中） | 5/5 | ≥4/5 ✅ |

结论：**暂不需要 ivfflat 向量索引**（当前 BM25 单路全量打分已远快于基线）。
数据量增长到十万级 chunk 时再评估，评估口径与脚本已就位。
